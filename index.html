EvoWeb

A benchmark for coding agents on evolving web applications

Can a coding agent keep an app working as the user keeps asking for more? EvoWeb gives agents 32 web apps to build and then extend, ten requests each. After every request, a browser agent tests the running app.

TL;DR

Building an app with an AI agent rarely ends at the first prompt. People come back to add features, and each new request lands on code the agent wrote earlier. Existing benchmarks score a single build. EvoWeb scores the whole journey.

  • No agent keeps an app fully working. The best, Fable 5 and Kimi K3, reach a Grade of about 0.69 out of 1.
  • Connecting features is the hard part. For every model, the tests that combine a new feature with an earlier one score lowest.
  • Apps keep building but stop running. Build failures stay rare, but runtime errors rise from about 2% after the first request to about 12% by the tenth.

Watch an app evolve

This is one real run: Fable 5 builds a website for a medical clinic, then grows it over nine follow-ups with a team directory, a cost estimator, appointment requests, a front-desk board, live search, a brand refresh and a Spanish version. Each feature is adapted from a real clinic's website. After each request the judge runs five checks: three on the new feature, one that combines it with an earlier feature, and one re-run of an earlier check. Step through the requests and click any check.

This is Fable 5 at its best: 48 of 50 checks pass. Only two get half credit. The first build's contact form has no phone field, and the judge wasn't sure about the wording of one notice. Even so, a user who expects perfection leaves after the very first request. That is why EvoWeb scores every level of patience, not just one.

Scored for real users

Most sequential benchmarks stop at the first failure, as if every user quits right away. Others score every request, as if no one ever quits. EvoWeb instead averages over every level of patience. Drag the slider to see how much of this app a user with a given tolerance actually gets.

Not everyone asks in English

People describe what they want in their own language, even when the app itself is in English. We translated every request into French, German, Chinese, Hindi and Hebrew and kept everything else the same: the apps, the tests and the judge. Only Sonnet 4.6 holds steady, staying within 0.03 of its English Grade in every language. Other models swing in both directions, even in widely spoken languages. GLM 5.2 drops to 0.445 in German but reaches 0.602 in Hebrew, and GPT 5.6 Luna falls from 0.277 in English to 0.198 in French. Agents should be tested in the language their users write in.

Try it

Run any model, whether through an API or served locally with vLLM, on all 32 apps:

RUN
git clone https://github.com/two-delta/EvoWeb.git && cd EvoWeb
docker build -f harness/Dockerfile -t evoweb-harness:latest .
pip install -r requirements.txt && pip install -e .

evoweb run --name haiku --model anthropic/claude-haiku-4-5
python3 -m evoweb.score_run runs/haiku
