EvoWeb

A benchmark for coding agents on evolving web applications

Can a coding agent keep an app working as the user keeps asking for more? EvoWeb gives agents 32 web apps to build and then extend, ten requests each. After every request, a browser agent tests the running app.

The short version

Building an app with an AI agent rarely ends at the first prompt. People come back to add features, and each new request lands on code the agent wrote earlier. Existing benchmarks score a single build. EvoWeb scores the whole journey.

  • No agent keeps an app fully working. The best, Fable 5 and Kimi K3, reach a Grade of about 0.69 out of 1.
  • Connecting features is the hard part. For every model, the tests that combine a new feature with an earlier one score lowest.
  • Apps keep building but stop running. Build failures stay rare, but runtime errors rise from about 2% after the first request to about 12% by the tenth.
  • More effort doesn't mean better results. Fable 5 leads while using the fewest agent turns per request.

Watch an app evolve

This is one real run: Fable 5 builds a solar-energy dashboard, then grows it over nine follow-ups with panels, a savings calculator, alerts, reports, a power-flow diagram and a health score. Each feature is adapted from a real product, SolarEdge or Enact Solar. After each request the judge runs five checks: three on the new feature, one that combines it with an earlier feature, and one re-run of an earlier check. Step through the requests and click any check.

Fable 5 does well until request 6, which adds an expected-generation baseline to the chart. The new feature works, but it takes "actual" output from the dashboard's history instead of the Panels page built in request 2. The system ends up reading over 300% of expected and "Healthy". Four of its five checks fail or only partly pass. Nothing tells the agent, so three requests later the same check fails again. This is the kind of failure EvoWeb is designed to catch: each feature works on its own, and the bug is in how they connect.

Scored for real users

Most sequential benchmarks stop at the first failure, as if every user quits right away. Others score every request, as if no one ever quits. EvoWeb instead averages over every level of patience. Drag the slider to see how much of this app a user with a given tolerance actually gets.

How it works

  • Grounded in real products. Every follow-up adapts a feature from a real website with a similar purpose, so apps grow the way real products do.
  • Built on dependencies. Each app's requests form a hidden dependency graph, so later features rely on earlier ones.
  • Tested in a real browser. A browser agent clicks through the live app after every request. It agrees with human reviewers on 87.7% of checks.

Try it

Run any model, whether through an API or served locally with vLLM, on all 32 apps:

RUN
git clone https://github.com/two-delta/EvoWeb.git && cd EvoWeb
docker build -f harness/Dockerfile -t evoweb-harness:latest .
pip install -r requirements.txt && pip install -e .

evoweb run --name haiku --model anthropic/claude-haiku-4-5
python3 -m evoweb.score_run runs/haiku
