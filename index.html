Can coding agents keep building the app they started?

EvoWeb gives coding agents 32 web apps to build and then keep extending, one request after another: 320 requests in all. After every request, a browser agent tests the running app.

The short version

Building an app with an AI agent rarely ends at the first prompt. People come back to add features, and each new request lands on code the agent wrote earlier. Existing benchmarks score a single build. EvoWeb scores the whole journey.

  • No agent keeps an app fully working. The best, Fable 5 and Kimi K3, score a Grade of about 0.69 out of 1.
  • Connecting features is the hard part. For every model, the tests that combine a new feature with an earlier one score lowest.
  • Apps keep building but stop running. Build failures stay rare, but runtime errors rise from about 2% after the first request to about 12% by the tenth.

Watch an app evolve

This is one real run: Opus 4.8 builds a stock-report site, then grows it over nine follow-ups into a small investing workspace. After each request the judge runs five checks: three on the new feature, one that combines it with an earlier feature, and one re-run of an earlier check. Step through the requests and click any check.

At request 3, the screener's add-to-watchlist buttons get cut off at the table's edge. That single bug fails three checks across two requests. Then the app recovers and scores 100% on four of the last five requests. Whether that recovery counts depends on the user.

Scored for real users

Most sequential benchmarks stop at the first failure, as if every user quits right away. Others score every request, as if no one ever quits. EvoWeb instead averages over every level of patience. Drag the slider to see how much of this app a user with a given tolerance actually gets.

More effort doesn't mean better results. Fable 5 tops the board with the fewest agent turns per request, while Sonnet 4.6 writes more than twice its tokens and scores lower.

How it works

  • Grounded in real products. Every follow-up adapts a feature from a real website with a similar purpose, so apps grow the way real products do.
  • Built on dependencies. Each app's requests form a hidden dependency graph, so later features rely on earlier ones.
  • Tested in a real browser. A browser agent clicks through the live app after every request. It agrees with human reviewers on 87.7% of checks.
